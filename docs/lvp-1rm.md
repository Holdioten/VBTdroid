# LVP / 1RM 现状与已知问题

**更新**：2026-11-10

## 当前算法

1. 每个训练组取一个点：`loadKg` + 该组有效次 MCV 平均值（`mcvAvgMps`）。
2. 同一负荷的多次组先取平均。
3. 至少 **3 个不同负荷**，否则不估算。
4. 最小二乘拟合 `v = intercept + slope × load`（slope < 0）。
5. 在 MVT（V1RM）处反解：

```
1RM = (MVT - intercept) / slope
```

6. 默认 MVT：深蹲 0.30、卧推 0.17、硬拉 0.25 m/s，来源标记 `literature`。
7. 输出 slope、intercept、R²、estimated1RmKg。

这是标准 L-V 线性回归方法，与文献一致；问题在数据范围和统计门槛。

## 已知问题

### P0：没有运动员维度

`lift_profiles` 与 `sets` 查询只按 `lift + variant`：

```sql
WHERE lift = :lift AND variant = :variant
```

分析别人的视频会把自己的历史混进同一条 L-V 曲线，1RM 不可用。

修复方向：

- `sets` 增加 `athleteId`；
- `lift_profiles` 主键改为 `(athleteId, lift, variant)`；
- 导入时选择/新建运动员；
- 历史、LVP 查询按运动员过滤；
- MVT 按运动员覆盖默认值。

### P1：缓存不失效

`AnalysisRepository.profile()` 命中 `lift_profiles` 就直接返回；新增组后没有失效/重算逻辑，1RM 会停留在第一次计算的结果。

修复方向：保存新组时删除对应 profile，或按 `updatedAt` 判断重算。

### P1：组质量未筛选

当前所有带负荷和 MCV 的组都进回归，包括：

- 热身组；
- 非最大意图组；
- 高次数/高速度损失组；
- 技术/节奏组。

这些组速度低于个人 L-V 线，会低估 1RM。

修复方向：

- 组类型标签：最大意图 / 工作组 / 热身 / 技术组；
- 只使用最大意图/工作组；
- 次数 1–6；
- 组内速度损失 ≤ 20–25%；
- 无法标注时用 robust 回归降权离群点。

### P2：无拟合质量门槛

只要求斜率 < 0、1RM > 0；R² 很低也输出 1RM。

修复方向：

- R² ≥ 0.90 才给 1RM，否则只显示曲线并标低置信度；
- 负荷跨度至少 3 个点且最高/最低差 ≥ 20% 预估 1RM；
- 输出标准误/95% 区间。

### P2：MVT 固定为文献值

没有个人 MVT 校准；个体差异会让 1RM 偏差。

修复方向：允许录入实测 1RM 反推个人 MVT，按运动员保存。

### P3：非最大意图组仍可用于其它指标

它们不适合 1RM，但可用于：

- 同负荷速度趋势；
- 疲劳/速度损失；
- 技术分析。

不要因为不进 1RM 就丢弃。

## 状态

当前只记录，不改算法。优先顺序：运动员维度 → 缓存失效 → 组质量筛选 → R² 门槛。
