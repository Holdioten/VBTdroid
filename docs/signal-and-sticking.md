# 信号处理与粘滞区：一致性与参数

**更新**：2026-11-10

目标是**泛用一致**：同一段动作在不同帧率、分辨率、远近端选择、不同动作下，速度指标和粘滞区判定不因处理参数而改变。本文记录最终参数与验收口径。

## 1. 为什么按“秒”而不是按样本数

同一段卧推视频（1440×1080）：

| 输入 | 平均窗口 | 覆盖时间 | 峰值速度 |
|---|---|---|---|
| 60 fps | 9 帧 | 0.15 s | 0.40 m/s |
| 30 fps | 9 帧 | 0.30 s | 0.36 m/s |

60 fps 下平滑时间减半，检测框 1–3 px 的抖动被放大成 0.1 m/s 量级的假峰，粘滞区落在动作起始 5–10%。

因此所有窗口都以秒定义，运行时用中位帧间隔换算成**奇数样本数**（`SampleWindow.samplesFor`）。

## 2. 参数

| 环节 | 参数 | 深蹲 / 硬拉 | 卧推 |
|---|---|---|---|
| 像素去毛刺（TrackSmoother） | 窗口 | 0.18 s | 0.18 × 1.15 = 0.21 s |
| 平均/推进速度（Kinematics mean） | 窗口 | 0.30 s | 0.30 × 1.15 = 0.345 s |
| 峰值速度（Kinematics peak） | 窗口 | 0.15 s | 0.15 × 1.15 = 0.17 s |
| 多项式阶数 | — | 2 | 2 |

卧推乘数的依据：双臂独立稳定杠铃，且近端片像素比例更高，60 fps 下的高频残差明显大于深蹲。乘数只影响平滑时间，不改变任何判定定义。

## 3. 粘滞区判定

定义不变：**Vpeak1 → Vmin**，末端主动减速不算。

在平均速度曲线上：

1. **极值最小间隔 0.10 s**：更近的极值视为同一次形变，不重复计数；
2. **显著性** `prominence = max(5 cm/s, 8% × 向心峰值速度)`；
3. **Vpeak1 位置 ≥ 15% 向心 ROM**：起始段是速度爬升 + 阶段边界，不能作为峰；
4. Vpeak1 之后、速度首次超过 Vpeak1 之前，找第一个落差 ≥ prominence 的局部谷作为 Vmin；
5. **必须存在 Vpeak2**：Vmin 之后速度回升 ≥ prominence，否则不出粘滞区（`null`，UI 不画色块）；
6. 平台最小值取平台最后一个样本；
7. 输出 `startPct`、`endPct`（`stickingPointPct = endPct`）、Vpeak1/Vmin 速度与所用 prominence。

Python 参考实现（`prototype/vbtdroid_proto/metrics.py`）使用同一组阈值，golden 对照测试保持同构。

## 4. 标定

- 参考片径 = **前 0.30 s 检测框高的中位数**（最多 24 帧，至少 5 帧）；
- 同时做一次**外缘直径估计**：以框中心为圆心、36 条射线在 0.90–1.35 倍半径内找最强梯度，要求 ≥18 条射线有效、四分位距 ≤8%、直径落在框高的 0.90–1.45 倍；通过则用外缘中位数，否则回退框高中位数；
- 外缘估计**只用于标定**，不参与逐帧位置，因此不会把几何噪声带进速度；
- 标定全程固定，不逐帧重算。

近端片的检测框通常比外缘小 6–8%，直接用框高会把速度高估同样的比例。同一条视频远近端 MCV 差 14.7%，按外缘重算后约 5.8%。

## 5. 质量标记

- `TRACK_NOISY`：轨迹高频残差（5 帧去趋势后的 RMS）> 1.5 mm 时写入。峰值速度可信度下降，但 MCV/ROM 仍可用。
- 原有 `NON_MONOTONIC_CONCENTRIC`、`NO_LOCKOUT`、`LATERAL_DRIFT` 等保持不变。

## 6. 验收口径

| 指标 | 目标 |
|---|---|
| MCV 跨 30/60 fps、1080p/720p | ≤ 2% |
| 峰值速度跨帧率 | ≤ 10% |
| 同视频远近端 MCV（外缘标定后） | ≤ 5% |
| 粘滞区存在性一致 | ≥ 80% |
| 粘滞区位置一致 | ±10% ROM |
| 卧推向心显著峰（5 cm/s） | ≤ 3 |

验收视频：卧推 1440p60 原件（远/近）、其 720p30 转码、深蹲 150 kg、硬拉 130 kg。

## 7. 验证记录（卧推 107.5 kg，App 实际分析）

| | 远端 | 近端 |
|---|---|---|
| App px/m | 647.0 | 1009.4 |
| App MCV 均值 | 0.2154 | 0.2470 |
| 回放 MCV（时间窗口） | 0.2163 | 0.2524 |
| 30 fps 回放 MCV | 0.2192 | 0.2539 |

时间窗口把 60 fps 峰值从 0.40 降到 0.37（30 fps 0.36）；近端残余的 4–5 个峰来自检测框中心抖动（高频残差约为远端 2 倍），由 `TRACK_NOISY` 提示，不再改动平滑参数。
