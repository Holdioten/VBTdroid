# 项目状态

**更新**：2026-11-04

## 1. 已完成（代码层）

- Android 多模块（`app` + `core`），arm64 debug APK ~62MB
- 导入：3 页横向流程（视频 / 框选 / 参数），SAF，首帧预览
- 自动 ROI：EfficientDet-Lite0 多裁剪（全图/顶60%/底60%）；手动 ROI 可移动/缩放/重置/锁定
- 跟踪：Hough 圆主跟踪（1.35×片径搜索）+ 椭圆回退 + 光流预测 + 量测门限
- 标定：片径 cm 输入→米；45° 水平反投影；固定参考片径
- 姿态：MediaPipe 多候选，选离杠铃最近的人；按动作只算相关关节；可关闭
- 指标：MCV/MPV/PV/ROM/速度损失/粘滞点/力/功率/LVP/1RM/质量
- 阶段：深蹲/卧推四阶段；硬拉正向速度段；1/4 次中位数 ROM 过滤
- 后台：前台服务分析，Activity 离开/回来恢复进度和结果
- 叠加视频：分析 + overlay 合并为单个后台任务；骨架/环点/角度/逐 rep 双色轨迹/速度胶囊/数据卡片；硬件 AVC 优先
- 报告：视频优先，视频驱动当前 rep、卡片、游标；左列窄卡片；轨迹卡无游标
- 历史：Room 保存/列表/详情/同负荷查询；LVP 消费端
- 手机 UI：暗色主题、Arcus 密度、仅保留叠加视频保存，JSON/CSV 隐藏

## 4. 已知问题/风险

- **并发 Gradle 会损坏 APK**：已写入 `AGENTS.md`；必须单构建 + clean 修复。
- **叠加导出慢**：硬件编码器优先已加，但未实测；逐像素 Bitmap→YUV 仍可能是瓶颈。
- **时间对齐**：报告/卡片/游标假设 overlay MP4 播放时间 = 源视频时间；有偏移会错位。
- **旧历史缓存**：overlay 缓存只保留最新几个，旧历史可能“叠加视频不可用”。
- **手动阶段校正**：不会重新生成 overlay MP4，视频内阶段仍是生成时的。
- **姿态精度**：单目 2D；45° 为近似校正；卧推肩外展误差更大。
- **无 ground truth 精度报告**：没有 LPT/力台对照的 Bland–Altman/ICC 数据。
- **45°/卧推**：样例只有侧拍深蹲/硬拉；45° 与卧推真机验证不足。
- **模型资产**：`plate.tflite`/pose 不进 git；新环境需先下载。
- **licence**：检测器发布路径仍待 Apache-2.0 模型；当前为个人 MVP。
