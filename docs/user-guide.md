# 使用说明

面向使用者的操作手册。开发者请先读 [`../AGENTS.md`](../AGENTS.md)。

## 1. 安装

- Android 手机（arm64），直接安装 `VBTdroid.apk`。
- 首次打开时系统可能提示"未知来源"，按系统提示允许即可。
- 应用完全离线运行，不会请求网络权限，视频和分析结果只留在本机。

## 2. 拍摄要求

算法只处理"专门拍摄、机位固定、杠铃片可见"的视频。满足下面几条，结果才可靠：

1. **机位固定**，不要手持、不要移动/变焦。
2. **杠铃片完整可见**，尽量正对镜面，不要被身体或架子挡住。
3. 画面里**只出现一个主要运动的人**；背景尽量不要有其他人。
4. 侧拍（90°）或前/后 45°，与设置里的「机位角度」一致。
5. 每个视频只包含一种动作，最长 10 分钟。
6. 深蹲、卧推、硬拉三大项；奥举、跳跃、跑步不在支持范围。

## 3. 分析流程

顶部三个步骤：

### 3.1 视频

- 点「选择视频」，从系统文件选择器里选一段视频。
- 选中后会显示首帧、时长、分辨率、有效帧率。
- 时长超过 10 分钟会被拒绝，需要先裁剪。

### 3.2 框选

- 应用会自动给出**杠铃片**的候选区域，一般就是正确的位置。
- 如果候选不对（框到了别的东西），手动拖动/缩放选框，框住一侧的杠铃片。
- 框选范围应略大于片子本身（至少 1.35 倍片径），太小会让跟踪漂移。
- 确认无误后点「确认区域」。

### 3.3 参数

| 字段 | 说明 |
|---|---|
| 动作 | 深蹲 / 卧推 / 硬拉 |
| 动作变式 | 深蹲：高杠/低杠；硬拉：传统/相扑 |
| 负荷 | 本组重量（kg），可留空；只用于 1RM 估算和负荷相关指标 |
| 杠铃片直径 | **cm**，默认 45。必须和视频里的片子一致，单位换算应用自动处理 |
| 机位角度 | 侧拍 90°，或前/后 45° |
| 姿态分析 | 默认开启；关闭后不计算关节角，速度/ROM 等不受影响 |

确认后点「开始分析」。

> 如果这段视频和这组参数**之前分析过**，按钮会变成「查看上次结果」，并出现「重新分析」。
> 「查看上次结果」直接打开上次的记录；「重新分析」强制重跑一遍，会新增一条记录。
> 同一段视频换了重量/变式/角度不会被复用，会正常重新分析。

## 4. 报告

分析完成后直接进入报告页，内容就是**叠加视频**：

- 骨架、杠铃轨迹、角度、速度读数都烧录在画面里；
- 左侧/右侧数据卡片：MCV、速度、姿态、轨迹、逐次数据，按主题配色；
- 视频时间与源视频一致，可以暂停、拖动查看某一帧。

底部的「保存」把叠加视频导出到相册 `Pictures/VBTdroid`。

## 5. 历史记录

- 每条记录：左上动作/变式，右上分析时间；下面依次是 **重量、次数、MCV**，再下面是速度损失。
- 点开详情可看每一次的 MCV、ROM、相位时间，以及缓存的叠加视频。
- 叠加视频只保留最近 10 个；更早的记录会显示"缓存已清理"，需要视频就重新分析。
- 从详情返回会回到原来的滚动位置。

## 6. 1RM 估算

- 入口：历史页右上角「1RM 估算」。
- 选动作和变式后，列表按**每一组**列出重量、次数、MCV。
- **每组单独作为拟合点，不做任何合并**；至少选 3 个不同重量才能估算。
- 结果标注"仅供参考"，保留一位小数。
- 如果估算值低于你实际举起过的最大重量，结果判为不可用——这是物理下限保护。
- 估算记录保存在历史页顶部，按动作/变式只显示最新一条。

## 7. 设置

右上角齿轮：

- **主题**：浅色红 / 深色红 / Arcus。主题切换后，新分析烧录的卡片用新配色；已分析视频的卡片不会改变。
- **清理缓存**：删除缓存的叠加视频和调试文件。需要二次确认；清理后旧记录的视频无法再播放，需要重新分析。

## 8. 已知限制

- 只支持固定机位的单机位视频；手持、变焦、快速横移会导致跟踪中断。
- 画面里有多人时，姿态只取离杠铃最近的人。
- 杠铃片被遮挡超过约 1 秒，这一段 rep 会被丢弃。
- 1RM 估算基于 LVP 线性拟合，数据点少、重量跨度小时误差很大，仅供训练参考。
- 卧推的姿态追踪可靠性低于深蹲/硬拉，默认关闭。
- 叠加视频导出耗时与视频长度相关，长视频建议在充电时处理。

## 9. 常见问题

**Q：分析失败/一直没结果？**
先确认视频满足第 2 节的拍摄要求；再看框选是否框到了杠铃片。仍失败时换一段光线更好、片子更清晰的视频。

**Q：速度比实际偏大或偏小？**
优先检查「杠铃片直径」和「机位角度」是否填对，这两个直接决定标定比例。

**Q：历史里的视频点开是黑的？**
该记录的叠加视频缓存已被清理（只保留最近 10 个），点「重新分析」重新生成。

**Q：为什么次数比实际少？**
半程动作、ROM 明显偏小的一次会被过滤（按中位数 ROM 判定）；遮挡导致的跟踪断裂也会丢弃对应片段。
